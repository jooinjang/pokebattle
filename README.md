1세대 포켓몬 151마리 중에서, **타입 상성만으로** 5마리 엔트리를 골라주는 CLI입니다.
개체값·종족값·기술·특성은 일절 쓰지 않습니다. 타입 조합이 전부입니다.

```bash
git clone https://github.com/jooinjang/pokebattle.git
cd pokebattle

python3 pokebattle.py            # 상대를 모를 때 (기본)
python3 scout.py                 # 기록된 상대를 정찰
python3 test_pokebattle.py       # 검증 (약 6초)
```

- 의존성 없음 (Python 표준 라이브러리만). Python 3.8+
- 파일 2개: `pokebattle.py`, `test_pokebattle.py`
- 데이터(151마리 타입 + 18타입 상성표)는 PokeAPI에서 생성해 파일에 직접 넣어뒀습니다. 네트워크 접속 없음

**정찰용 부가 파일** — `scout.py` (매치 기록으로 특정 상대의 균형 이탈·슬롯 습관·최적
카운터를 분석), `match-samples.json` (익명화된 예시 기록). 본체와 독립이며
[11절](#11-정찰-scoutpy) 참고.

## 1. 게임 규칙

이 프로그램이 전제하는 규칙입니다.

**1판 판정** — 서로에게 낼 수 있는 **가장 강한 공격 배율**을 비교해 높은 쪽이 이깁니다.

```
내 배율   = max(내 타입 각각이 상대 타입 조합에 내는 배율)
상대 배율 = max(상대 타입 각각이 내 타입 조합에 내는 배율)
```

- 물 vs 불꽃 → 물이 2배, 불꽃이 0.5배 → **물 승**
- 배율이 같으면 **무승부**. 같은 타입 조합끼리는 항상 무승부
- 둘 다 0배여도 무승부 (노말 vs 고스트)

**시리즈** — 슬롯끼리 1:1로 5판. 다승 팀이 승리, 승수가 같으면 시리즈 무승부.

**엔트리 제약** — 기본은 **서로 다른 포켓몬 5마리**입니다. 타입 조합이 같은 다른
포켓몬은 괜찮습니다 (코일 + 레어코일 = OK).

같은 포켓몬을 중복으로 넣을 수 있는 규칙이라면 **`--dup`** 을 붙이세요.
이 차이가 답을 꽤 많이 바꿉니다 — [6.4절](#64-중복-금지가-만든-함정) 참고.

**상성표** — 현행 18타입 표(강철·페어리 포함)를 씁니다. 포켓몬은 1세대 151마리지만
타입은 현행 기준입니다. 레어코일은 전기/강철, 삐삐는 페어리입니다.

## 2. 빠른 시작

### 상대를 전혀 모를 때 (양쪽 동시 제출)

```bash
python3 pokebattle.py
```

내쉬 균형 표를 먼저 보여주고, 거기서 뽑은 엔트리 5마리를 제시합니다.
**실행할 때마다 달라집니다.** 그게 정상입니다 — 고정 엔트리는 반드시 카운터당합니다.

### 상대 엔트리를 알 때

```bash
python3 pokebattle.py 리자몽 거북왕 이상해꽃 뮤츠 갸라도스
```

슬롯 순서대로 5마리를 적으면 각 슬롯의 확정 카운터를 배정합니다. 항상 5:0이 나옵니다.

### 일부만 알 때

```bash
python3 pokebattle.py 리자몽 ? 피카츄 ? 레어코일
```

아는 슬롯은 카운터로 착취하고, `?` 슬롯은 균형에서 뽑습니다.

### 같은 상대와 반복해서 붙을 때

기록을 `matches.json` 에 쌓아두면 그 상대의 습관을 착취할 수 있습니다.

```bash
python3 scout.py 상대팀명 --hide 강철/전기
```

**이게 실전에서 가장 효과가 큽니다.** 상대가 균형에서 벗어나 있으면 착취 가능성이
수치로 나오고, 우리 주력을 노리는 저격 픽이 어느 슬롯에서 오는지까지 드러납니다.
자세한 건 [11절](#11-정찰-scoutpy).

## 3. 명령어 레퍼런스

```
python3 pokebattle.py [슬롯1 슬롯2 슬롯3 슬롯4 슬롯5] [--dup] [--seed N]
python3 pokebattle.py --rank
python3 pokebattle.py --maxev [--dup]
python3 pokebattle.py --selftest

python3 scout.py [상대팀명] [--hide 타입/조합]
python3 scout.py <상대팀명> --arrange <포켓몬 5마리>
python3 test_pokebattle.py
```

세 파일의 역할이 다릅니다.

| 파일 | 언제 쓰나 |
|---|---|
| `pokebattle.py` | 상대를 모른다. 균형 전략이 필요하다 |
| `scout.py` | 상대 기록이 있다. 습관을 착취하고 싶다 |
| `test_pokebattle.py` | 코드나 데이터를 건드렸다. 깨졌는지 확인 |

### 슬롯 인자

5개를 전부 적거나, 하나도 안 적거나 둘 중 하나입니다. 개수가 5가 아니면 오류로 종료합니다(exit 1).

| 형식 | 예 | 의미 |
|---|---|---|
| 한국어 이름 | `리자몽` | 그 슬롯 상대를 안다 |
| 도감 번호 | `6` | 위와 동일. 1~151 |
| `?` `-` `_` | `?` | 그 슬롯 상대를 모른다 |

이름은 정식 한국어 명칭입니다. 니드런처럼 성별 기호가 들어가는 이름(`니드런♀`, `니드런♂`)은
터미널에서 입력하기 번거로우니 도감 번호 `29`, `32`를 쓰는 게 편합니다.

모르는 이름을 넣으면 오류로 종료합니다.

```
$ python3 pokebattle.py 파이카츄 ? ? ? ?
모르는 포켓몬: '파이카츄' (1세대 한국어 이름 또는 1~151 도감번호)
```

### `--seed N`

미지 슬롯 추출을 고정합니다. 같은 시드 + 같은 인자 → 항상 같은 결과.
인자 사이 어디에 넣어도 됩니다.

```bash
python3 pokebattle.py --seed 42 6 ? 25 ? 82
python3 pokebattle.py 6 ? 25 ? 82 --seed 42     # 동일
```

디버깅이나 결과 공유용입니다. **실전에서는 시드를 고정하지 마세요.** 무작위성이 이 전략의 전부입니다.

### `--dup`

같은 포켓몬을 엔트리에 여러 번 넣을 수 있는 규칙으로 전환합니다. 기본은 중복 금지입니다.

```bash
python3 pokebattle.py --dup
python3 pokebattle.py --dup --maxev
python3 pokebattle.py --dup 리자몽 리자몽 피카츄 ? ?
```

**중복이 허용되면 이 게임은 완전히 풀립니다.** 정원 제약이 사라져서 슬롯마다 균형에서
독립으로 뽑을 수 있고, 그러면 시리즈 수준 착취력이 **정확히 0**이 됩니다.
중복 금지판에 남는 +0.039가 사라집니다.

| | 중복 금지 (기본) | `--dup` |
|---|---|---|
| 미지 슬롯 추출 | 5마리를 한 덩어리로 (최대엔트로피) | 슬롯마다 독립 |
| 라운드 착취력 | 정확히 0 | 정확히 0 |
| **시리즈 착취력** | **+0.039** | **정확히 0** |
| 아는 슬롯 카운터 | 배정 문제 (중복 회피) | 슬롯마다 독립으로 최선 |
| `--maxev` 엔트리 | 코일, 레어코일, 갸라도스, 썬더, 야돈 | 코일·레어코일로 5칸 |

### `--rank`

151마리를 타입 상성 강도순으로 전부 나열합니다. 지표는 **151마리 전원과 1:1로 붙였을 때의
(승 + 무÷2) ÷ 151**.

```
순위  포켓몬        타입              점수     승   무   패
1     코일          전기/강철       0.7483   106   14   31
1     레어코일      전기/강철       0.7483   106   14   31
3     갸라도스      물/비행         0.7086    76   62   13
4     야돈          물/에스퍼       0.6954    78   54   19
...
149   캐터피        벌레            0.3477    22   61   68
```

같은 타입 조합은 성능이 완전히 동일하므로 동점 처리합니다. 조합이 달라도 점수가 같으면
역시 동점입니다 (물/에스퍼와 전기/비행은 승무패 내역이 다른데 둘 다 105/151).

### `--maxev`

**상대가 적응하지 않는다**고 가정했을 때 기대값이 가장 높은 엔트리를 보여줍니다.

```
최대기대값 엔트리: 코일, 레어코일, 갸라도스, 썬더, 야돈
  판당 기대점수 0.7192
```

랜덤 상대 기준 시리즈 승률 84.67%. 다만 이 엔트리에는 **확정 카운터가 262개** 있습니다.
자세한 건 [5절](#5-어떤-모드를-써야-하나).

### `--selftest`

내장 검증을 돌립니다. 즉시 끝납니다. 상성표 데이터와 균형 상수가 맞는지 확인합니다.

```
$ python3 pokebattle.py --selftest
selftest ok
```

`--rank`, `--maxev`, `--selftest`는 다른 인자보다 먼저 처리되고 즉시 종료합니다.
`--seed`와 같이 써도 무시됩니다. `--dup`은 `--maxev`와 슬롯 지정 모드에만 영향을 줍니다
(`--rank`는 개별 포켓몬 지표라 중복 규칙과 무관합니다).

## 4. 출력 읽는 법

```
슬롯 상대                    추천                        내 배율     상대 배율  판정
--------------------------------------------------------------------------
1    리자몽(불꽃/비행)       꼬부기(물)                     2         1  승
2    ? (미지)                코일(전기/강철)                             균형추출 p=27.4%
3    피카츄(전기)            이상해씨(풀/독)                1       0.5  승
4    ? (미지)                아쿠스타(물/에스퍼)                         균형추출 p=9.7%
5    레어코일(전기/강철)     파이리(불꽃)                   2         1  승
--------------------------------------------------------------------------
엔트리: 꼬부기(물), 코일(전기/강철), 이상해씨(풀/독), 아쿠스타(물/에스퍼), 파이리(불꽃)
확정 슬롯 3판 중 3승 0무 0패
미지 슬롯 2개는 균형에서 무작위 추출 — 재실행하면 달라집니다 (--seed N 으로 고정).
```

| 항목 | 의미 |
|---|---|
| 내 배율 / 상대 배율 | 서로에게 낼 수 있는 최대 배율. 큰 쪽이 이깁니다 |
| 판정 | 그 슬롯의 확정 결과. 상대를 아는 슬롯에만 나옵니다 |
| 균형추출 p=27.4% | 그 타입 조합이 균형에서 뽑힐 확률. 이 판의 승패 예측이 **아닙니다** |
| 확정 슬롯 N판 중 … | 아는 슬롯만 집계. 미지 슬롯은 빠져 있습니다 |

**주의** — `균형추출 p`를 승률로 오해하기 쉽습니다. 그 슬롯이 왜 그 포켓몬으로 채워졌는지
설명하는 확률일 뿐, 이길 확률이 아닙니다.

미지 슬롯이 하나라도 있으면 균형 분포표가 먼저 출력됩니다.

```
1판 게임의 내쉬 균형. 각 슬롯이 이 확률을 따르므로 어떤 상대 엔트리를 만나도
판당 기대 승패는 0 이상이다. 5마리는 정원 제약 때문에 독립이 아니라 한 덩어리로 뽑는다.

  17/62 = 27.42%  강철/전기      코일, 레어코일
  16/62 = 25.81%  땅             모래두지, 고지, 디그다, 닥트리오, 탕구리, 텅구리
   8/62 = 12.90%  비행/전기      썬더
   6/62 =  9.68%  땅/바위        꼬마돌, 데구리, 딱구리, 롱스톤, 뿔카노, 코뿌리
   6/62 =  9.68%  물/에스퍼      야돈, 야도란, 아쿠스타
   4/62 =  6.45%  얼음/에스퍼    루주라
   2/62 =  3.23%  물/비행        갸라도스
   2/62 =  3.23%  벌레/풀        파라스, 파라섹트
   1/62 =  1.61%  불꽃/비행      리자몽, 파이어
```

## 5. 어떤 모드를 써야 하나

**상대가 내 엔트리에 맞춰 대응하느냐** 하나로 갈립니다.

| | vs 안 맞추는 상대 | vs 최악의 대응 |
|---|---|---|
| `--maxev` 고정 엔트리 | **승 84.67%** 무 9.4% 패 6.0% | **승 0% 패 100%** |
| 기본 (균형 추출) | 승 63.85% 무 16.9% 패 19.2% | 승 37.2% 무 21.7% 패 41.1% |

- **한 번만 붙는다 / 상대가 캐주얼하다** → `--maxev` 엔트리를 고정으로 쓰세요
- **같은 상대와 반복한다 / 상대도 최적화한다** → 인자 없이 실행해서 매번 새로 뽑으세요

균형 추출은 최악의 경우에도 4%p 뒤지는 게 전부입니다. 대신 만만한 상대에게서 뽑을 수 있는
21%p를 포기합니다. **보험료라고 생각하면 됩니다.**

고정 엔트리가 위험한 이유는 예외가 없기 때문입니다. `--maxev` 엔트리를 상대로
실현 가능한 66만 개 엔트리를 전수 평가하면, **순서와 무관하게 100% 이기는 확정 카운터가
262개** 있습니다. 가장 단순한 둘:

```
꼬마돌, 데구리, 딱구리, 롱스톤, 뿔카노   (땅/바위 ×5)
피카츄, 라이츄, 찌리리공, 붐볼, 에레브    (전기 ×5)
```

균형 추출에는 이런 확정 카운터가 존재하지 않습니다.

**중복이 허용되는 규칙이면 `--dup`을 붙이세요.** 균형 추출 쪽 최악값이 -4%p에서
정확히 0으로 개선됩니다. 그 경우 균형 추출은 어떤 상대에게도 지지 않는 게 증명됩니다.

### 슬롯 순서

미지 슬롯은 프로그램이 자동으로 균등 무작위 배치합니다. 손대지 마세요.

엔트리가 같아도 순서 배치는 그 자체로 게임입니다. 예컨대 양쪽 다 `--maxev` 엔트리를
가져오면 내부 상성이 `코일 = 레어코일 > 썬더 > 갸라도스 = 야돈` 인 완전한 서열이라,
전기(田忌)의 경마와 같은 구조가 됩니다 — **가능한 배치 120가지가 전부 최선 대응에게
100% 집니다.** 균등 무작위 배치만이 exploitability 0입니다.

## 6. 작동 원리

### 6.1 포켓몬이 아니라 타입 조합

승부를 가르는 건 타입 조합뿐이라 개체는 의미가 없습니다. 151마리는 **고유 타입 조합
37종**으로 줄어듭니다. 코일과 레어코일은 이 게임에서 완전히 같은 존재입니다.

타입 순서는 무시합니다. 꼬마돌(바위/땅)과 뿔카노(땅/바위)는 같은 조합입니다.

### 6.2 아는 슬롯 — 배정 문제

슬롯별로 독립이므로 5×151 점수 행렬을 만들고 중복 없이 배정하면 됩니다.
슬롯이 5개뿐이라 **슬롯당 상위 5후보만 남겨도 최적 배정이 그 안에 존재**합니다
(좌측 정점 k개인 최대 가중 이분 매칭은 각 정점의 상위 k개만 봐도 충분).
그래서 완전탐색이 5⁵ = 3,125 가지로 끝납니다.

### 6.3 모르는 슬롯 — 내쉬 균형

양쪽이 동시에 제출하므로 "랜덤 상대 대비 최강"은 답이 아닙니다. 상대도 최적화하니까요.
1판 게임(37×37 대칭 제로섬)의 내쉬 균형을 **유리수로 정확히** 풀었습니다.

분모 62, support 9종, **exploitability는 37개 순수전략 전수 확인상 정확히 0**입니다.
근사값이 아닙니다. `--selftest`가 실행할 때마다 `Fraction`으로 재검증합니다.

### 6.4 중복 금지가 만든 함정

여기가 이 프로그램에서 가장 까다로운 부분입니다. **`--dup`을 쓰면 이 절 전체가
해당 없음이 됩니다** — 슬롯마다 독립으로 뽑으면 끝이고, 시리즈 착취력도 0입니다.
아래는 중복 금지(기본)일 때의 이야기입니다.

균형은 `강철/전기`에 27.4%를 요구하는데 해당 포켓몬은 코일·레어코일 **2마리**뿐이고,
`비행/전기`에 12.9%인데 썬더 **1마리**뿐입니다. 5슬롯에 중복이 안 되면
**슬롯마다 독립으로 뽑아서는 이 확률을 물리적으로 실을 수 없습니다.**

시도한 방법 셋:

| 방법 | 라운드 착취력 | 시리즈 착취력 |
|---|---|---|
| 독립 추출 + 기각 | +0.15 | — |
| Madow 계통추출 | ~0 | +0.143 |
| **최대엔트로피 (채택)** | **정확히 0** | **+0.039** |

계통추출은 주변분포는 맞췄지만 결합분포가 모수 하나로 결정돼서 **서로 다른 엔트리를
9개밖에** 만들지 않았습니다. 다수결 승부는 결합분포에 의존하기 때문에 그대로 착취당합니다.

채택한 방법은 5마리를 한 덩어리로 뽑되 두 가지를 동시에 만족시킵니다:

1. **슬롯 주변분포 = 균형 그대로** → 라운드 수준 착취력 정확히 0
2. **결합분포 = 최대엔트로피** (정원 조건부 독립)

구현은 실현가능한 멀티셋을 전부 나열하고, 조건화 후 주변분포가 균형이 되도록
IPF로 가중치를 기울이는 것입니다. `nash_multiset_dist()`를 보세요.

**`--dup`이 왜 이걸 전부 없애는가.** 정원 제약이 사라지면 슬롯마다 독립으로 뽑아도
각 슬롯이 정확히 균형 분포를 따릅니다. 그러면 라운드마다 승 확률 ≥ 패 확률이고,
독립인 확률변수의 합은 자기 부호반전을 확률적으로 지배하므로 다수결에서도
P(시리즈 승) ≥ P(시리즈 패)가 따라옵니다. 상대 엔트리 749,398개 전수에서
우위 > 0 인 것이 **0개**임을 확인했습니다 (test [12]).

### 6.5 순서를 모르면 기대값이 분해된다

양쪽 다 순서를 모르면 대진이 무작위 전단사가 되고, 교차항이 사라집니다.

```
E[내 승점] = Σ(내 5마리 각각의 개별 점수)
개별 점수(c) = Σ_y q(y) · duel(c, y)      # q = 가정한 상대 분포
```

그래서 `--maxev`와 `--rank`는 조합 탐색 없이 개별 점수 정렬만으로 답을 냅니다.
테스트 [11]이 순열 120가지 전수와 대조해 이 성질을 고정합니다.

단, **합산(다수결)은 기대값과 다른 목적함수**입니다. 기대값이 같다면 분산이 낮은 쪽,
즉 패가 적은 쪽이 유리합니다. 물/에스퍼(19패)와 비행/전기(15패)는 둘 다 105/151점으로
기대값이 같은데, 후자를 넣으면 시리즈 승률이 84.45% → 84.67%가 됩니다.
`--maxev`의 동점 처리가 이 규칙을 씁니다.

## 9. 한계와 가정

**시리즈 수준에서 +0.039가 남습니다 (중복 금지 모드만).** 라운드 수준은 정확히 0이지만,
다수결이 기댓값의 부호를 보존하지 않아서 생기는 차이입니다.
`땅/바위` 5마리 엔트리를 만나면 상대가 3.9%p 유리합니다 (승 37.2% / 패 41.1%).
상대 후보 480개 전수 검사에서 나온 최악값입니다.

**`--dup`에서는 이 값이 정확히 0이라 이 한계가 해당하지 않습니다.** 규칙이 중복을
허용한다면 그쪽을 쓰는 게 무조건 낫습니다.

중복 금지 상태로 완전히 닫으려면 37개 조합 전체의 5-멀티셋(약 66만 개) 위에서
double oracle을 돌려야 하고, 결과물은 9개 상수 대신 수백 개 멀티셋 테이블이 됩니다.

참고로 다수결 게임을 12개 조합으로 제한해서 풀어본 적이 있는데(2,738개 멀티셋,
RM 200만 회, 제한 게임 내 exploitability 0.00018) **더 나빴습니다** — 제한 밖의
`독/땅`·`전기`에게 +0.134로 착취당했습니다. 슬롯 주변분포가 균형에서 벗어난 게 원인입니다.

**그 밖의 가정:**

- 기술·종족값·특성·아이템·날씨 전부 무시합니다. 순수 타입 상성 게임입니다
- 상대의 순서 배치는 균등 무작위라고 가정합니다. 상대가 특정 배치를 편애하면 착취 여지가 있지만, 프로그램은 그걸 학습하지 않습니다
- 일부만 아는 모드에서 미지 슬롯의 균형 계산은 그 슬롯 개수에 맞춰 다시 풉니다. 다만 아는 슬롯이 썬더·루주라·갸라도스 같은 유일 포켓몬을 먼저 가져가면 균형 support가 좁아져 근사가 됩니다
- 상대가 균등 랜덤이라는 가정(`--rank`, `--maxev`)은 실제 사람의 픽 분포와 다를 수 있습니다

### 데이터를 다시 만들려면

`CHART`와 `MONS`는 PokeAPI에서 생성했습니다. 상성표를 바꾸고 싶으면(예: 1세대 오리지널
상성표로) 두 상수를 갈아끼우면 됩니다. **단 `NASH` 상수는 현재 상성표에 대한 해라서,
상성표를 바꾸면 균형도 다시 풀어야 합니다.** 안 풀고 두면 `--selftest`가
`착취 가능:` 메시지와 함께 실패합니다.

균형을 다시 푸는 절차는 이렇습니다.

1. 37×37 반대칭 페이오프 행렬 `A[i][j] = duel(i,j)*2-1` 을 만든다
2. regret matching 자가대전으로 support를 찾는다 (10만 회면 충분)
3. 그 support에서 `(Ap)_i = 0`, `Σp = 1` 을 `Fraction`으로 정확히 푼다
4. 해가 유일하지 않으면(반대칭 행렬은 rank가 짝수라 흔히 그렇습니다) 자유변수를 훑어
   `p >= 0` 이면서 exploitability가 정확히 0인 꼭짓점을 잡는다
5. `NASH`에 넣고 `--selftest`로 검증한다

4번을 건너뛰면 안 됩니다. 현재 해도 support 위에서 균형이 **선분**으로 존재했고,
그 선분의 한쪽 끝(어떤 좌표가 0이 되는 꼭짓점)에서만 exploitability가 0이었습니다.
RM 근사값을 그대로 쓰면 0.0005 정도가 남습니다.

`pokebattle.py` 는 상대를 모를 때의 균형 전략을 다룹니다. `scout.py` 는 반대로,


### 대전 기록 추가하기

`match-samples.json` 을 `matches.json` 으로 복사해서 시작하거나, 빈 파일을 직접 만듭니다.

```bash
cp match-samples.json matches.json     # 샘플로 시작
```

```json
{
  "us": "Team A",
  "matches": [
    {
      "left": "Team B", "right": "Team A", "score": "1:4",
      "slots": [["롱스톤", "야돈"], ["라프라스", "코일"], ["파라스", "코일"],
                ["썬더", "야도란"], ["포니타", "갸라도스"]]
    }
  ]
}
```

| 필드 | 내용 |
|---|---|
| `us` | 내 팀 이름. 전적 표에 `<- 우리` 로 표시됩니다 |
| `left` / `right` | 두 팀 이름. 화면에 왼쪽/오른쪽으로 표시된 그대로 |
| `score` | `"왼쪽승수:오른쪽승수"`. **무승부 판은 세지 않습니다** |
| `slots` | 1번부터 5번까지 `[왼쪽팀 포켓몬, 오른쪽팀 포켓몬]`. 대진 순서 그대로 |

적을 때 지킬 것:

- **포켓몬은 정식 한국어 이름**으로. 틀리면 `모르는 포켓몬` 오류가 납니다
- **`slots` 순서를 화면 그대로** 옮기세요. 슬롯 분석이 전부 이 순서에 달려 있습니다
- **새 매치는 배열 끝에** 추가하세요. 최신 경기에 가중치를 주는 분석이 순서를 봅니다
- `score` 는 승수만 셉니다. 5판 중 2승 1패 2무면 `"2:1"` 입니다

**스크립트가 `score` 를 상성 엔진으로 재계산해 대조합니다.** 옮겨 적다 틀리면 바로 걸립니다.

```
$ python3 scout.py
기록 검증 실패:
  매치3  표기 2:1 != 계산 1:1
```

이게 걸리면 그 매치의 포켓몬 이름이나 순서를 잘못 옮긴 것입니다. 실제로 이 검증에
여러 번 걸렸고, 매번 기록 쪽 오류였습니다.

출력에 담기는 것:

- 전 팀 전적
- 그 상대가 낸 엔트리 전부와 타입 조합 분포 (균형 확률과 나란히)
- **균형 support 비중**과 **라운드 착취 가능성** — 균형 상대라면 각각 100%, 0.000
- `--hide` 를 주면 그 조합을 잡는 저격 픽의 **슬롯별 출현 횟수와 경기별 추이**
- 관측 엔트리 전부를 상대로 한 순수 5칸 엔트리 성적 순위

슬롯 히트맵이 특히 쓸모 있습니다. 저격이 한 번도 안 온 슬롯이 드러나면, 저격당하는 픽을
거기 숨기고 저격을 잡아먹는 픽을 저격이 오는 슬롯에 두는 배치가 나옵니다.

### 균형 구성 + 정보 기반 배치

`--dup` 은 슬롯 순서를 균등 무작위로 섞습니다. 그게 착취 불가능성의 일부지만, 상대
슬롯 습관을 아는 경우에는 순서를 맞추는 편이 낫습니다. **멀티셋은 균형에서 뽑고
배치만 정보로 결정**하는 하이브리드입니다.

```bash
python3 pokebattle.py --dup                       # 예: 썬더 코일 썬더 고지 갸라도스
python3 scout.py 개발16유닛 --arrange 썬더 코일 썬더 고지 갸라도스
```

슬롯별 경험분포(라플라스 평활)로 기대 마진 합이 최대인 배치를 완전탐색(5!=120)합니다.
출력에 균등 배치와의 차이가 함께 나오니, 이득이 미미하면 순서를 신경 쓸 필요가 없습니다.

실제로 한 판을 뒤집은 사례가 있습니다 — 같은 멀티셋을 `--dup` 이 뽑은 순서로 내서
1승 4패로 졌는데, `--arrange` 배치는 3승 2패 승리였습니다.

**대가**: 배치를 맞추는 순간 균형의 착취 불가능성은 깨집니다. 상대가 슬롯 습관을
바꾸면 그 이득이 그대로 손실이 됩니다. 관측이 얇을 때(2~3경기)는 쓰지 마세요.

### 실전 흐름

1. `scout.py <상대>` — 균형 이탈 정도와 착취 가능성을 확인
2. `scout.py <상대> --hide <우리 주력 조합>` — 저격이 안 오는 슬롯을 찾는다
3. 저격당하는 픽을 그 슬롯에 숨기고, 저격을 잡아먹는 픽을 저격이 오는 슬롯에 둔다
4. 배치를 맞출지 결정 — 습관이 뚜렷하면 `--arrange`, 아니면 `--dup` 순서 그대로
5. 매치가 끝나면 `matches.json` 에 추가 (스크립트가 표기 점수를 재검증한다)

### 슬롯 베팅을 언제 하고 언제 말아야 하나

슬롯 패턴에 거는 엔트리는 **기록된 순서로는 대승이지만 상대가 순서를 바꾸면 무너집니다.**
`scout.py` 는 슬롯 출현 횟수를 그대로 보여주니 직접 판단하세요. 대략의 기준:

- **베팅할 만함** — 관측 5경기 이상, 특정 슬롯에 저격 0회가 일관되고, 균형 support 비중이 낮다(착취 여지가 크다)
- **베팅하지 말 것** — 관측 3경기 이하, 또는 상대가 균형에 가깝다. 이때는 한 조합을 집중해서 도배하는 쪽이 순서와 무관하게 안정적이다

표본이 얇다는 점은 잊지 마세요. 몇 경기는 습관을 보여주긴 해도 보장하지 않습니다.
상대가 이쪽 카운터를 읽는 낌새가 보이면 `pokebattle.py --dup` 으로 돌아가는 게 안전합니다.
